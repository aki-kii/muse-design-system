# 原則

個別のルールで決めきれないときに、この4つで判断します。

パターンは、基本コンポーネントを組み合わせて、よくあるパターンにしたものです。新しい部品を作る前に、部品の組み合わせで組めないかを見ます。パターンに置くのは、組み合わせ自体に決まり（配置の意図、状態の連動、流れ）があり、実在のアプリで繰り返し使われているものだけです（[決定記録 0007](decisions/0007-pattern-admission.md)）。

## 1. 見た目はアプリに合わせ、形は中身で決める

色・書体・角丸・余白は Muse アプリの文法に揃える。画面の形（チャット／ページ／一覧）は中身の性質で決める。ブリーフのような読み物はページにし、会話はチャットにする。

## 2. アクセントはブルー1色

操作・選択・リンク・進捗はすべてブルー。色で意味を増やさない。予定の色分けのような「中身側の色」はテーマと分けて持ち、UI の色と混ぜない。

## 3. 部品には必ず状態と使い分けを付ける

デモだけでは部品として登録しない。通常、押下、無効、完了などの状態を決め、どういうときに使うかまで書く。書き方は [部品のテンプレート](components/_template.md) に揃える。

## 4. 余白と整列で階層を作る

装飾で目立たせない。見出しの太さ、余白の大きさ、罫線で階層を作る。本文は 16px、タップ範囲は 44px 以上、フォーカスは常に見える形にする。
