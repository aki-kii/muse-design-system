# 判断待ちの点

デザインの判断が要るため、このリポジトリでは値や使い分けを変えずに残している点です。決まったら値を直し、[決定記録](decisions/README.md) に移します。

## 色

1. **`--fill` と `--bg` の差がほぼない。** 静的ページ版では背景 `#FAFAFA` より `--fill`（`#F0F0F2`）が暗かったが、アプリの背景 `#EDEEF0` に合わせた結果、`--fill` のほうがわずかに明るくなった（比 1.02:1）。カードの外に置いたチップや第2ボタンが背景と見分けられない。`--fill` をアプリの背景に合わせて調整するか、「`--fill` はカードの中だけで使う」と決めるか。
2. **`--faint` のコントラストが足りない。** ライトで `--surface` に対して 3.3:1、`--bg` に対して 2.9:1。時刻・注記・完了したタスクの題に使っている。値を濃くするか、用途を「読めなくても困らないもの」に限ると明記するか。
3. **ブルーとレッドの文字を `--bg` に直接置くと 4.5:1 に届かない。** `--accent` は 3.9:1、`--danger` は 4.2:1（ライト）。カードの中（`--surface`）なら届く。
4. **ダークの `--ok` が 3.6:1。** 静的ページ版でもダークの値が定義されておらず、ライトと同じ `#12805C` になっている。
5. **アプリにないトークンの値。** `--fill`、`--faint`、`--accent-strong`、`--accent-soft`、`--danger`、`--ok`、吹き出し、影は、静的ページ版の値のまま。アプリの濃いめの色合い（本文 `#0B0D10`、アクセント `#0073E6`）に合わせて調整するか。

## フォーカス

6. **フォーカスの輪が見えにくい。** `--accent-soft` の 3px の輪は、面に対して 1.1〜1.2:1 で、WCAG 2.2 の基準（3:1）に届かない。入力欄は枠が `--accent` に変わるので見えるが、ボタン・チップ・タブでは見えにくい。輪を `--accent` にするか、`--accent-soft` の輪の内側に `--accent` の線を足すか。

## 余白・角丸・文字

7. **「余白は4の倍数」と実際の値が合わない。** 静的ページ版には「余白は4の倍数」とあるが、カード同士 14px、カードの内側 18px は4の倍数ではない。ルールを書き直すか、値を 12/16 などに寄せるか。このリポジトリでは値を残し、ルールの文は載せていない。
8. **数値タイルの角丸 14px が角丸の段にない。** 段は 6/12/20/999。12 か 20 に寄せるか。
9. **タイポの段のサイズ（13・15・17・22・28・38px）が文字サイズのスケール（12・14・16・18・20・24・30・36・48px）に乗っていない。** 段をスケールに合わせるか、段のサイズをスケールに足すか。本文の行間も、段では 1.55、スケールでは 24px（1.5）と違う。
10. **タブの大きさ。** 静的ページ版の仕様の表は 52×44px、見本の実装は 56×44px。どちらを正にするか。

## 学習ノート由来の部品

v0.4.0 で足した学習ノートの部品に必要で、まだトークンがない値です。部品の文書では「未定義」と書き、値は決めていません。参考に、モック（静的ページ版 v0.3 の値で作ったもの）と元の学習ノートで使っていた値を書きます。

11. **金色のトークンがない。** 完了したノードの面、XP の文字、章完了の ★、章をまたいだときの祝福の帯、本棚の区切りの ★ に使っている。モックは `#F5B400`（ダーク `#FFC933`）、帯の文字は `#4A3200`。白の ★ を金色の面に載せると 1.8:1、金色の XP の文字を白い面に置くと 1.8:1 で、どちらも 3:1 に届かない。`--gold` のような役割のトークンを足すか、完了を `--ok` で示すか。
12. **正解・不正解の薄い面がない。** [クイズ選択肢](components/quiz-option.md)と[結果バナー](components/result-banner.md)の面。モックは `--ok-soft`（`#E2F2EA`、ダーク `#12291F`）と `--danger-soft`（`#FDECEA`、ダーク `#3A1D1A`）。トークンに足すか。あわせて、「答え合わせ」のボタンを緑（`--ok`）の面にするか（[ボタン](components/button.md)に緑のバリアントはない）。
13. **コースとノートの色（中身側の色）がない。** Part 見出しの面、コースのアイコン、本棚の表紙に、コースやノートごとの色を使っている。モックは `#0082FB`、`#0E7C86`、`#F08A24`、`#12805C`、`#606770`。白い文字・アイコンを載せたときの比は 3.8、4.9、2.5、4.9、5.7:1 で、オレンジは 3:1 にも届かない。カレンダーの色と同じ「中身側の色」としてパレットを決めて登録するか。本棚の進捗バーを `--ok` にしている点（ほかの進捗は `--accent`）もここで決める。
14. **紙吹雪の色。** モックは `#EC4561`、`#0082FB`、`#F5B400`、`#12805C` の4色で、DS の色と一致していない。既存のトークン（`--accent`、`--ok`、`--danger` と、11 で決める金色）から選ぶか。
15. **選択肢の正誤が色だけ。** クイズ選択肢の正解・不正解は枠と面の色だけで示している。結果バナーの文で補っているが、選択肢そのものに ✓ ✕ などの印を付けるか。
16. **段にない寸法。** ノードの円の立体の影（下に 4px ずらした影。`--shadow-*` にない）、コースのアイコンの角丸 8px と 14px（角丸の段にない）、単語の 36〜52px と ★ の 64px（タイポの段にない）、「今ここ」のラベル 11px（Small 段の 12px より小さい）、コース切替パネルの幕（黒の 40%）。段に足すか、近い段に寄せるか。
17. **アイコンの決まりがない。** 学習ノートの部品は ✕・🔊・★・▶ を文字や絵文字で出している。線のアイコンの組を決めるか、このままにするか。

## スライドエディタ由来の部品

v0.5.0 で足したスライドエディタの部品に必要で、まだトークンや決まりがない点です。部品の文書では「未定義」と書き、値は決めていません。参考に、モック（静的ページ版 v0.3 の値で作ったもの）と元のスライドエディタで使っていた値を書きます。

18. **スライドの地と面、スライドの中の色。** [スライドステージ](components/slide-stage.md)の地はグレー（`#EDEEF0`）、スライドは白い面で、モックはダークモードでもこの2色のまま固定している。地を `--bg` に連動させる（ダークでは黒）か、スライドの見え方を保つために固定の「スライドの地」として登録するか。スライドの中の色（文字 `#22304A`・`#3C4C68`・`#8A94A6`、強調 `#D92D20`・`#0082FB`、図の `#7A86D8`・`#4A56C4`・`#E8A04C` など、コードの面 `#141A26`）はデッキ側の色として DS に入れない、と決めてよいか（カレンダーの色と同じ「中身側の色」の扱い）。
19. **色の面に載せる白がない。** `--accent` の面には `--accent-ink` があるが、`--ok`（[解決済みバッジ・完了トグル](components/done-toggle.md)）と `--danger`（[確認ダイアログ](components/confirm-dialog.md)の「削除する」、[FAB](components/speed-dial-fab.md)の件数バッジ、[メモ入力バー](components/memo-input-bar.md)の音声入力中）の面に載せる白は、モックで `#fff` を直接書いている。`--ok-ink`・`--danger-ink` を足すか。ダークの `--ok` が未定義（4）なことと合わせて決める。
20. **幕の色が3つある。** [シートモーダル](components/sheet-modal.md)は黒の 55%、[確認ダイアログ](components/confirm-dialog.md)は黒の 96%（モックは `rgba(10,10,12,…)`）、[コース切替パネル](components/course-switcher.md)は黒の 40%（16）。`--scrim` のような役割のトークンを1つか2つ（軽い・重い）に決めるか。
21. **ページプレビューの黒い枠。** [ページプレビューカード](components/page-preview-card.md)の枠は黒（`#000`）の面に白の 70%（「なし」は 40%）の文字で、どのトークンにもない。スライドの縮小として黒にするか、`--fill` の面と `--dim` の文字に寄せるか。
22. **本人の吹き出しの色がモックと DS で違う。** モックは静的ページ版 v0.3 の値で、本人の吹き出しを濃いブルー（`#0082FB`）に白い文字、メタ行を白の 75% にしている。DS の `--bubble-user` は薄いブルー（`#D9EBFF`）に `--bubble-user-ink`。[吹き出し](components/message-bubble.md)は DS の値を正として書いたが、スライドエディタも DS の値に揃えてよいか。あわせて、吹き出しの本文 14px・内側 8px 16px・最大幅 85%（DS は 15px・12px 16px・84%）をどちらに寄せるか。
23. **段にない寸法。** 丸ボタンの見た目 32px（押せる範囲は外側に 6px 広げて 44px にしている）、FAB の 48px、件数バッジの 20px と 2px の縁、修正中の点の 6px、長押しメニューの幅 176px。文字の 13px・11px・10px（Small 段の 12px より小さい）。押せる範囲が 44px に届かないもの: [ページカウンタ行](components/page-counter-row.md)のリンク（36px）、[長押しメニュー](components/long-press-menu.md)の項目（40px）。余白は全体に 16px で、`--space-card-padding`（18px）と `--space-card-gap`（14px）を使っていない。段に足すか、近い段に寄せるか。
24. **完了・無効の薄さがそろっていない。** 完了した[依頼行](components/request-row.md)と解決済みの[スレッドカード](components/thread-card.md)は行全体を不透明度 0.7、題を `--dim` ＋打ち消し線にしている。[リスト行](components/list-rows.md)のタスク行は題を `--faint` にし、不透明度は使わない。無効は[ボタン](components/button.md)が 0.45、FAB の項目と全幅ボタンが 0.4、ヘッダーの再読み込み中が 0.5。完了と無効の見せ方を1つずつに決めるか。なお、`--bg` の上で行全体を 0.7 にすると、`--dim` の題は 4.0:1 になり 4.5:1 に届かない。
25. **「完了」の色が2つある。** [完了トグル](components/done-toggle.md)は `--ok`（緑。元のアプリは `#2F9E44`）、[リスト行](components/list-rows.md)のタスク行の完了は `--accent`（ブルー）。「本人のタスクの完了」と「依頼が片付いた」で色を分けるのか、どちらかに揃えるか。
26. **ボタンの形と色の例外。** [シートモーダル](components/sheet-modal.md)の全幅ボタンと[確認ダイアログ](components/confirm-dialog.md)のボタンは角丸 12px（[ボタン](components/button.md)はピル）で、確認ダイアログの「削除する」は赤い面（ボタンの決まりでは危険操作はゴースト）。シートやダイアログの中の確定ボタンを「フォームの一部」として 12px と赤い面を認めるか、ピルとゴーストに寄せるか。
27. **`--danger` をエラー以外に使っている。** FAB の下書きの件数バッジと、メモ入力バーの音声入力中のマイクが赤い面。色の決まりでは `--danger` は「削除・拒否・エラーだけ」。件数バッジを `--accent` にする、録音中を別の色にする、または決まりに「録音中」「未送信の件数」を足すか。
28. **アイコンの組（17 の候補）。** スライドエディタは Lucide 風の線のアイコン（24 の枠、線 2〜2.6px、端は丸、16〜20px）で統一している。これを DS のアイコンの組として決めれば、17（学習ノートの文字・絵文字のアイコン）の答えにもなる。
