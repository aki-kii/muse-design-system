# 0008: コンポーネントは汎用の言葉だけで書き、パターンは世の中でよくある型に限る

- 状態: 決定
- 日付: 2026-11-17

## 背景

[0002](0002-component-admission.md) と [0007](0007-pattern-admission.md) では、アプリ固有の複合体をパターンに置き、単一部品のアプリ固有のバリアントは部品の文書に出自のアプリを添えて書くことにしていた。その結果、次の2つが起きた。

- コンポーネントの文書に、「デッキ」「ページを追加」のような特定のアプリのユースケースに寄ったバリアント名や例が残り、汎用の部品として読みにくくなった。
- パターンが「自分のアプリで繰り返し出た画面の組み合わせ」になり、ほかの画面を作る人が使える「よくある型」になっていなかった。

## 決定

1. コンポーネントは汎用のままに保つ。 名前・バリアント・状態・例に、特定のアプリの言葉やユースケースを書かない。例と見本は架空の汎用的な内容にする。
2. 特定のアプリでしか使わない組み合わせやバリアントは、DS に置かずアプリ側で持つ。（0002 の 2〜4・7 と、0007 を置き換える）
3. パターンは、世の中の多くの製品に出てくるタスクや状態の型だけを置く。 例: 読み込み・空・失敗の状態、失敗からのやり直し、検索と絞り込み、一覧から詳細へ、確認をはさむ操作、フォームの流れ。各パターンの冒頭に「よくある型である理由」を、参考にした公開のデザインシステムやガイドラインとともに書く。
4. ただし、Muse のアプリで実際に使っている型だけを載せる。 実績のない型は作らない。冒頭に「使っているところ」を書く。
5. 部品とパターンのページには、その部品・パターンそのものを描いた見本を必ず載せる。

## 結果

- v0.12.0 で、パターンを 6件から 5件にし、すべて入れ替えた。外したもの: 読み物ページの型、状態を見せる型、答え合わせの型、単語カード、質問ボックス。足したもの: 読み込み・空・失敗の状態、失敗からのやり直し、検索と絞り込み、一覧から詳細へ。承認をはさむ型は、確認ダイアログと合わせて「確認をはさむ操作」に広げた。
- コンポーネントから、アプリに寄ったバリアント（メディアカードのデッキ・本棚、選択肢ボタンのクイズ・位置、進捗パスのコース、アイコンボタンの英語の読み上げ）と使用例を外し、汎用の名前と例にした。シートモーダルはボトムシートに改名し、バリアントを入力・削除・一覧・上から出すにした。
- 困ること: 外したパターンとシートモーダルの URL は開けなくなる。転送のページは作らない。アプリ側の細かい決まり（学習ノートのコースパスなど）は、v0.11.0 のタグとアプリのソースに残る。
