版の付け方

Muse DS は Semantic Versioning（MAJOR.MINOR.PATCH）で版を付けます。版番号は package.json の version に書き、リリースのたびに v0.3.0 の形の git タグを付けます。

どの番号を上げるか#

このリポジトリはドキュメントとトークンを持つので、「使っている側が直す必要があるか」で決めます。

上げる番号当てはまる変更例
MAJOR使っている側が直さないと壊れる、または見た目が意図せず変わるトークンの削除・改名、部品の廃止、「使うとき／使わないとき」の判断の反対向きの変更
MINOR足すだけで、今の使い方はそのまま動くトークンの追加、部品やパターンの追加、バリアントの追加
PATCH判断を変えない修正誤字、説明の補い、リンクの修正、コントラストを満たすための小さな値の調整

トークンの値を変えるときは、見た目が変わる範囲で判断します。全体の印象が変わる変更（アクセント色の変更など）は MINOR 以上にします。

1.0.0 になるまで#

0.x の間は、MINOR を上げる変更に壊れる変更も含めてよいことにします（semver の 0.x の扱いに従う）。その場合は CHANGELOG の該当版に「壊れる変更」として明記します。

1.0.0 にする目安:

  • 判断待ちの点 がすべて決まっている
  • 2つ以上のアプリやスペースに適用して、トークンの名前を変える必要がなくなっている

変更の手順#

  1. 変更を入れる。トークンなら tokens/tokens.json を直し、npm run tokens で tokens.css を作り直す。
  2. CHANGELOG.md の [Unreleased] に、Added／Changed／Deprecated／Removed／Fixed のどれかで1行書く。
  3. 判断を伴う変更は docs/decisions/ に決定記録を足す。
  4. リリースするとき、[Unreleased] を版番号と日付に置き換え、package.json の version を上げ、タグを付ける。
git tag v0.3.0
git push origin v0.3.0

廃止の手順#

トークンや部品をなくすときは、すぐに消さず、まず CHANGELOG の Deprecated に書いて1つ以上の MINOR 版のあいだ残します。消すのは次の MAJOR 版（0.x の間は次の MINOR 版）です。

GitHub で元の文書を見る（docs/versioning.md）
