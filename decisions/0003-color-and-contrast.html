0003: 色の値と使い方を、実アプリの現行値と WCAG の基準で決める

  • 状態: 決定
  • 日付: 2026-11-17

背景#

v0.6.0 までの判断待ちの点のうち、色に関わるもの（1〜6、11〜14、18〜22、25、27）がまとまって残っていた（番号は v0.6.0 時点の判断待ちの一覧のもの。一覧は v0.8.1 で廃止し、決定はこの記録に残す）。0001 でアプリの theme.css にあるトークンは揃えたが、アプリにないトークン、学習ノート・スライドエディタで足りなかった色、コントラストが届かない組み合わせが決まっていなかった。

決め方は次の順にした。

  1. 実アプリ（筋トレ記録・学習ノート・スライドエディタ・AWS アップデート）の現行値が正。
  2. コントラストに関わる数値は、WCAG 2.2 AA を満たす側を選ぶ。
  3. トークンは、実アプリが実際に使っているものだけを足す。
  4. 名前やスケールの食い違いは、文書の修正で済む側でそろえる。
  5. 今は決められないものも「当面の扱い」を決めて閉じる。

決定#

値を変えたもの#

トークン前後理由
--faint#8A8D91／ダーク #6E7278#656A72／ダーク #8E939A--surface で 3.3:1、--bg で 2.9:1 だった。--bg・--surface・--fill のどれでも 4.5:1 以上にした（基準2）
--ok（ダーク）未定義（ライトと同じ #12805C、3.6:1）#3ECF8E学習ノートとスライドエディタのダークの値（基準1）。8.9:1
--bubble-user#D9EBFF／ダーク #0E3A5F--accent と同じ（#0073E6／ダーク #5CA8FF）吹き出しを使っている実アプリはスライドエディタだけで、本人の吹き出しはブルーの面に白（基準1）
--bubble-user-ink#0C2D4D／ダーク #EAF4FF#FFFFFF／ダーク #0B0D10同上。メタ行も同じ色で、白の 75%（3.2:1）にはしない（基準2）

足したもの（基準3: 実アプリが使っている）#

トークンライトダーク使っているアプリ
--ok-soft・--danger-soft#E2F2EA・#FDECEA#12291F・#3A1D1A学習ノート（--good-soft・--bad-soft）
--ok-ink・--danger-ink#FFFFFF#0B0D10スライドエディタ・学習ノート（#fff を直接書いている）。ダークは白だと 2.0:1・2.8:1 のため黒（基準2）
--gold・--gold-ink#F5B400・#4A3200#FFC933・#2A1E00学習ノート（--gold・--gold-ink）
--scrim・--scrim-strong黒の 40%・70%同じ40% は筋トレ記録・AWS アップデート・学習ノート、70% はスライドエディタの入力のシート

値を変えず、使い方を決めたもの#

  • --fill と --bg（1）: 値は学習ノート・スライドエディタの現行 #F0F0F2 のまま。--fill は --surface の上だけで使い、--bg の上に置くチップや第2ボタンは --surface の面＋--border の枠にする（基準1・4）。
  • ブルーとレッドの小さい文字（3）: --accent はアプリの値なので変えない。ブルーの文字は --accent-strong（--bg の上で 4.8:1）を使い、--accent は面・枠・アイコン・大きい文字に使う。赤の小さい文字は --surface の上だけに置く（基準1・2・4）。
  • アプリにないトークンの値（5）: --fill・--accent-strong・--accent-soft・--danger・--ok（ライト）・影は、学習ノートとスライドエディタが同じ値を使っているので現行どおり（基準1）。--faint と --ok のダークだけ上の表のとおり変えた。
  • フォーカスの輪（6）: --accent の 2px の輪を 2px 離して描く。外側の面に対してライト 3.9〜4.6:1、ダーク 7.2〜8.5:1。--accent-soft は輪に使わない（基準2）。
  • 金色（11）: 金色は面と飾りだけに使い、文字の色にしない。金色の面の上の文字・★ は --gold-ink（6.5:1）。XP の数字は --text で書き、前に金色の ★ を飾りとして置く（基準3・2）。
  • 答え合わせのボタン（12）: 学習ノートの現行どおり緑の面にする。ボタンに「確認」のバリアント（--ok の面に --ok-ink）を足した（基準1）。
  • コースとノートの色（13）: コースやノートのデータが持つ値なので、DS のトークンにしない（中身側の色）。白の文字を載せる面に使う色は白に対して 4.5:1 以上を選ぶ。本棚の進捗バーは学習ノートの現行どおり --ok（読み終えるまでの進み）で、ほかの進捗は --accent（基準1・3・2）。
  • 紙吹雪（14）: 情報を持たない飾りなので、DS のトークンにしない。デモは学習ノートの現行の4色（#EC4561・#2F7CF6・#F5B301・#2E9E5B）にした（基準1・3）。
  • スライドの地と中の色（18）: ステージの地は --bg に連動させる（スライドエディタの現行で、ダークでは黒）。スライドの面と中の色はデッキ側の色で、DS に入れない（基準1・3）。
  • ページプレビューの枠（21）: スライドエディタの現行どおり、--surface の面・--border の枠・--dim の文字。「なし」は不透明度ではなく --faint で薄くする（基準1・2）。
  • 完了の色（25）: 2つを意味で分ける。本人が自分で付ける完了（筋トレのセット・タスク）は --accent（筋トレ記録の現行）、やりとりが片付いた（解決済み）・正解は --ok（スライドエディタ・学習ノートの現行）（基準1）。
  • --danger の用途（27）: 「削除・拒否・エラー」に「録音中」と「未送信の件数」を足した。スライドエディタの現行の使い方を、決まりの側で認めた（基準1・4）。

結果#

  • 本文に使う色の組み合わせは、ライト・ダークともすべて 4.5:1 以上になった（アクセシビリティ）。
  • --faint と吹き出しの色は見た目が変わる。--faint は前より濃く、本人の吹き出しは薄いブルーから濃いブルーになる。
  • 学習ノート・スライドエディタは DS と違う名前（--good・--surface-2 など）で同じ値を持っている。名前の対応は色に書いた。アプリを DS の名前に寄せるかは、各アプリに手を入れるときに行う。
  • 学習ノートの白の ★（金色の面の上）、XP の金色の文字、スライドエディタの行全体の不透明度 0.7 は、DS の決まりと違う。アプリ側は当面現行どおりで、次に手を入れるときに DS に合わせる。
