# 確認をはさむ操作（Confirm Before Acting）

**よくある型である理由:** 取り消せない操作や外部に影響する操作の直前に止まって確かめる流れは、削除・送信・購入のある製品ならほぼどこにでもある型です（[Carbon の Dialog pattern](https://carbondesignsystem.com/patterns/dialog-pattern/)、[NN/g の Confirmation Dialogs](https://www.nngroup.com/articles/confirmation-dialog/)）。

**使っているところ:** Muse（メール送信など外部に触る操作の承認）、スライドエディタ（中身ごと消える削除の確認）。

## 概要

操作の重さに応じて、実行の直前に確認をはさみ、結果をその場に残す流れです。アプリの中だけで済む取り消せない操作は[確認ダイアログ](../components/confirm-dialog.md)、アカウントや外部に触る操作は[承認カード](../components/approval-card.md)で止めます。確認のために別の画面へ移らせません。

## 組み合わせ

- 操作の入口: [ボタン](../components/button.md)の危険のゴースト、または[アイコンボタン](../components/icon-button.md)の危険
- 確認: [確認ダイアログ](../components/confirm-dialog.md)（アプリの中）／[承認カード](../components/approval-card.md)（外部）
- 結果: その場の行の変化＋[トースト](../components/toast.md)

## 流れ

| 段階 | 見た目 | 次へ進む条件 |
| --- | --- | --- |
| 操作を選ぶ | 削除・送信などの入口 | 押した |
| 確認待ち | 何が起きるか（誰が・何を・どこへ、何が消えるか）を1文で書き、やめる操作を必ず並べる | 確定かやめるを選んだ |
| 結果 | 確定したら実行し、結果をその場に残してトーストで知らせる。やめたら何もせず元の画面に戻す | |

- 確認の重さを操作の重さにそろえる。取り消せる操作、読み取りだけの操作には確認をはさまない（確認が増えると形だけになる）。
- 確定のボタンには、何が起きるかを動詞で書く（「削除する」「送信を許可」）。「OK」「はい」にしない。
- 承認カードでは許可の範囲（1回だけ／このタスク中）を選ばせる。「このタスク中は許可」を選んだら、同じタスクの同じ種類の操作ではカードを出さない。

## 使うとき

- 中身ごと消える削除、送信・予約・購入など、あとから戻せない操作の直前

## 使わないとき

- 取り消しで戻せる操作 → 確認せずに実行し、トーストで知らせる
- 入力や選択が要る → [ボトムシート](../components/bottom-sheet.md)で入力させてから確定する

## アクセシビリティ

- 確認が出たら、やめる側にフォーカスを置く（Enter の押し間違いで実行しない）。Esc はやめると同じにする。
- 結果は色だけでなく文で残す（「許可した（1回だけ）11:02」「削除しました」）。
