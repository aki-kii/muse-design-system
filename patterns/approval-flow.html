確認をはさむ操作（Confirm Before Acting）

取り消せない操作・外部に触る操作の直前に確認をはさみ、結果をその場に残す

デモ

見本: 外部に触る操作（提案 → 承認カード → 結果）

1. 提案の本文

会場の担当の方に、12/6 の利用時間を 18:30 からに変えたいと返信します。下の内容で送ってよければ許可してください。

2. 承認カード（範囲を選ぶ）

アシスタント が メールを送ろうとしています

宛先: 会場担当の方 ・ 件名「12/6 の会場の件」 ・ 本文 4 行

3. 結果の行

✓

途中で画面を移らず、その場に結果を残します。

見本: アプリの中の取り消せない削除（入口 → 確認ダイアログ → 結果）

旅行の写真

フォルダを削除して一覧に戻りました。

フォルダを削除しますか？

中の項目もすべて削除されます

よくある型である理由: 取り消せない操作や外部に影響する操作の直前に止まって確かめる流れは、削除・送信・購入のある製品ならほぼどこにでもある型です（Carbon の Dialog pattern、NN/g の Confirmation Dialogs）。

使っているところ: Muse（メール送信など外部に触る操作の承認）、スライドエディタ（中身ごと消える削除の確認）。

概要#

操作の重さに応じて、実行の直前に確認をはさみ、結果をその場に残す流れです。アプリの中だけで済む取り消せない操作は確認ダイアログ、アカウントや外部に触る操作は承認カードで止めます。確認のために別の画面へ移らせません。

組み合わせ#

  • 操作の入口: ボタンの危険のゴースト、またはアイコンボタンの危険
  • 確認: 確認ダイアログ（アプリの中）／承認カード（外部）
  • 結果: その場の行の変化＋トースト

流れ#

段階見た目次へ進む条件
操作を選ぶ削除・送信などの入口押した
確認待ち何が起きるか（誰が・何を・どこへ、何が消えるか）を1文で書き、やめる操作を必ず並べる確定かやめるを選んだ
結果確定したら実行し、結果をその場に残してトーストで知らせる。やめたら何もせず元の画面に戻す
  • 確認の重さを操作の重さにそろえる。取り消せる操作、読み取りだけの操作には確認をはさまない（確認が増えると形だけになる）。
  • 確定のボタンには、何が起きるかを動詞で書く（「削除する」「送信を許可」）。「OK」「はい」にしない。
  • 承認カードでは許可の範囲（1回だけ／このタスク中）を選ばせる。「このタスク中は許可」を選んだら、同じタスクの同じ種類の操作ではカードを出さない。

使うとき#

  • 中身ごと消える削除、送信・予約・購入など、あとから戻せない操作の直前

使わないとき#

  • 取り消しで戻せる操作 → 確認せずに実行し、トーストで知らせる
  • 入力や選択が要る → ボトムシートで入力させてから確定する

アクセシビリティ#

  • 確認が出たら、やめる側にフォーカスを置く（Enter の押し間違いで実行しない）。Esc はやめると同じにする。
  • 結果は色だけでなく文で残す（「許可した（1回だけ）11:02」「削除しました」）。
