読み込み・空・失敗の状態（Loading, Empty, Error）

データを読み込む場所ごとに、読み込み中・0件・読み込めなかったを出し分ける

デモ

メモ

見出しは残したまま、中身の場所だけを切り替えます。「もう一度読み込む」を押すと読み込み中に戻り、少しして中身が出ます。中身は架空です。

よくある型である理由: データを読み込んで見せる画面は、どの製品でも「読み込み中」「中身がない」「読み込めなかった」の3つの状態を持ちます。中身の画面だけを作ると、この3つが抜けがちです（Carbon の Loading pattern、Carbon の Empty states、Primer の Loading）。

使っているところ: 筋トレ記録（記録の一覧・日ごとの記録・種目の一覧）、学習ノート（コース・本棚・ノート）、スライドエディタ（デッキの一覧）、日々のレポートのスペース。どのアプリも一覧を開くたびにこの3つを出し分けています。

概要#

データを読み込んで見せる場所ごとに、中身が届くまで・届いた中身が0件・届かなかった、の3つを決めておく型です。どの状態でも、中身が出る場所と同じ位置・同じ大きさで見せ、画面の形を崩しません。

組み合わせ#

  • 読み込み中: スケルトン（中身の形だけを先に出す）
  • 中身あり: リスト行・メディアカード・セクションカードなど
  • 空: 空の状態の「まだない」（作る操作のボタンを添える）
  • 失敗: 空の状態の「読み込めなかった」＋「もう一度読み込む」

状態の移り方#

状態見せ方次へ
読み込み中中身と同じ形のスケルトン（一覧なら 3〜5件）届いたら中身ありか空へ。10 秒を超えたら失敗へ
中身あり中身の部品
空「まだない」の理由と、次にできること1つ作ったら中身ありへ
失敗「読み込めなかった」と、もう一度読み込む操作押したら読み込み中へ戻る
  • 3つの状態は、中身の場所の中で切り替える。画面全体を差し替えない（見出しや戻る操作は残す）。
  • 空と失敗を同じ文にしない。「まだない」と「読み込めなかった」では、本人がすることが違う。
  • 読み込み中に「読み込み中…」の文だけを出さない。中身の形が分かるスケルトンにする。

使うとき#

  • サーバーや端末からデータを読み込んで見せる一覧・詳細のすべて

使わないとき#

  • 操作の結果を待つ間（送信中など）→ ボタンの無効と文の切り替え。失敗したら失敗からのやり直し
  • 一覧の一部だけが空 → 一覧の中で行として見せる

アクセシビリティ#

  • 読み込む範囲に aria-busy="true" を付け、届いたら外す。スケルトンは aria-hidden="true"。
  • 空と失敗の文は、中身の場所に普通の文として置く。失敗は role="alert" にしない（読み込みのたびに割り込まない）。
