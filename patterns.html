パターン

部品の組み合わせの型です。画面を作る前に「どの型か」を決めると、形がそろいます。

A. 読み物ページの型#

ブリーフ・レポート・学習ノートなど「届いたものを読む」画面の型です。チャットにはしません。要約を最初に置き、話題ごとのカードを続けます。

組み立て: ページ見出し（Display＋メタ情報のチップ）→ 要約カード → セクションカードの列 → 注記

  • 使う部品: セクションカード、リスト行、チップとタグ
  • 使わない部品: 吹き出し、入力欄

B. 承認をはさむ型#

外部に触る操作の型です。実行の直前で必ず承認カードをはさみ、結果をその場に残します。途中の画面遷移で確認させません。

組み立て: 提案の本文 → 承認カード（範囲を選ぶ）→ 結果の行＋トースト

見本: 提案の本文 → 承認カード → 結果の行＋トースト

1. 提案の本文

会場の担当の方に、12/6 の利用時間を 18:30 からに変えたいと返信します。下の内容で送ってよければ許可してください。

2. 承認カード（範囲を選ぶ）

アシスタント が Gmail でメールを送ろうとしています

宛先: 会場担当の方 ・ 件名「12/6 の会場の件」 ・ 本文 4 行

3. 結果の行

✓

途中で画面を移らず、その場に結果を残します。

C. 状態を見せる型#

エージェントの状態表示の型です。深さを3層に分け、読む側が選べるようにします。全部を最初から並べません。

組み立て: ステータスのピル（いま何をしているか）→ 作業の流れ → 詳しいログ

D. 時間で区切るセッションの型#

1日の学習時間を決めて、段階を順に進める型です。英語のコースのように、単語・復習・講義を毎日同じ順番で回すときに使います。各段階の画面は部品で作り、この型は段階の順番と切り替えの規則だけを決めます。

組み立て: ✕＋コース名の見出し → 段階ごとの画面（単語 → 復習 → 講義）→ 章完了パネル（今日の分はおしまい）

段階画面次へ進む条件
単語単語カード。今日の復習の単語＋新しい単語（1日の数は設定で決める）を、始めた時点で固定した束にする束の最後のカードを判定した
復習復習の問題（クイズ選択肢、結果バナー）。進捗トラックと「n / m」最後の問題を終えて「講義へ」を押した
講義今日の章の名前と「はじめる」（途中なら「続きをはじめる」）のカード。押すと学習プレイヤーを開く。下に「今日はおしまい」「今日はおしまい」を押した
単語だけ「ここからは単語カードだけだよ」の注記＋単語カード＋「ホームへ」✕ か「ホームへ」で終わる
おしまい章完了パネル（単語を続ける／ホームへ）

切り替えの規則は次のとおりです。

  • 時間は段階の切り替えのときに確かめる。決めた時間（例: 15分）を過ぎていたら、次の段階へ進まず「単語だけ」にする。復習と講義の途中でも、時間を過ぎたら「単語だけ」に移る。
  • 残り時間は画面に出さない。時計を見せて急がせないため。
  • 中身のない段階は飛ばす（今日の単語がない → 復習へ、今日の復習がない → 講義へ）。
  • 単語の束の位置と復習の位置は日ごとに保存し、開き直したときに終わった段階を繰り返さない。
  • ✕ でいつでもホームへ戻れる。戻っても進んだ分は残る。
  • 使う部品: 単語カード、クイズ選択肢、結果バナー、模範解答ボックス、読み上げボタン、章完了パネル
  • 使わない部品: 今ここストリップ、コースパス（セッションの中ではパスを見せない）

E. スライドの型#

スライドステージやデッキカードのサムネイルに入る、スライド1枚の組み方の型です。スライドの中は DS の文字の段やトークンで塗らず、デッキ自身の見た目で描きます。この型は「どの型にどの要素を、どの順で置くか」だけを決めます。

組み立て: 型を1つ選ぶ → 上から順に要素を置く（見出しはどの型でも左上、表紙・中扉・終了だけは位置が違う）

型要素（上から）使うとき
表紙キッカー（イベント名）→ タイトル（2行まで）→ サブタイトル → 下端に発表者1枚目
見出し（中扉）縦の中央にタイトルだけ章の区切り
箇条書きタイトル → リード（任意）→ 箇条書き標準。迷ったらこれ
図右上に注記のラベル（任意）→ タイトル → リード → 図（破線の枠の中に箱と矢印、下にチップ）仕組みや関係を見せる。ほかの型より一段詰めて組む
箱並びタイトル → リード → 同じ幅の箱を横に3つ（題＋説明）並列の3つを比べる
引用タイトル → 枠で囲んだ引用 → リード（出典や補足）定義や言葉をそのまま見せる
コードタイトル → 暗い面のコード → 箇条書き（任意）手順やコマンド
大数字タイトル → 大きな数字（強調したい部分だけ色を変える）→ リード（何の数字か）1つの数字を見せる。数字には単位と比べる相手を添える
終了縦の中央にお礼の文 → 下に補足最後の1枚

組みの決まりは次のとおりです。

  • 寸法はスライドの幅に対する割合（cqw）で決める。表示の大きさ（ステージ・サムネイル）が変わっても同じ組みになる。比は 980:552。
  • 内側の余白は上下 6.5%・左右 7%（図の型は 4%・6%）。
  • 強調は太字＋1色だけにする（リードと箇条書きの中の <b>）。大数字の強調も同じ1色。
  • 1枚に型を混ぜない。図と箇条書きを両方入れたいときは2枚に分ける。

スライドの色（文字・強調・図の色）はデッキ側の色で、DS のトークンではありません（色）。

  • 使う部品: スライドステージ、デッキカード
  • 使わない部品: DS の部品はスライドの中に置かない（スライドは発表の資料で、アプリの画面ではないため）

見本: 9つの型（比 980:552、寸法はスライドの幅に対する割合）

スライドの中の色はデッキ側の色（中身側の色）で、DS のトークンではありません。

アプリ固有の複合体#

特定のアプリでしか使わない部品の組み合わせです。中身に依存しない汎用の部品はコンポーネントに、アプリの言葉（章・デッキ・スレッドなど）を持つ組み合わせはここに置きます（Carbon の Core と拡張の分け方にならう）。アプリごとには分けず、1つの一覧にしています。どのアプリで使っているかは、各文書の冒頭の「出自」と下の表に書いています。

別のアプリで同じものが要るときは、複合体をそのまま持ち出さず、「組み合わせ」の汎用部品で組みます。複合体をいつ部品に上げるかは決定記録 0002に決めています。

横断の約束#

  • アクセシビリティ: ファウンデーションの基準に従う。タップ範囲は 44px 以上、フォーカスは常に見える、本文のコントラストは 4.5:1 以上、色だけで状態を伝えない、動きは prefers-reduced-motion で止まる。
  • 文: タイポグラフィの文の約束に従う。見出しは名詞で短く、ボタンは動詞を含む短い文、数字には単位と「あとどれくらい」を添える。
